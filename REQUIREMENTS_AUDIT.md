# MyHub Requirements Audit

**Audit date:** 23 September 2026

**Scope:** the completed web application, end-to-end encrypted Supabase persistence, encrypted GitHub backup, uploaded calendars and cookbook, automated verification, and deliberate native-only boundaries

## Conclusion

The requested **web deliverables are complete and usable**. MyHub starts without inaccurate demo records, lets the user create and edit records in every major workflow, persists them immediately in IndexedDB, synchronizes the full `AppData` aggregate as client-encrypted Supabase ciphertext, and keeps the private `avicados14/MyHub-Data` repository as encrypted backup and calendar source.

A real-browser test against that repository decrypted **27 cookbook recipes**, imported both encrypted calendar feeds, retained **zero homework assignments**, and wrote the combined state back to `myhub-data/v1/snapshot.enc`. The corrected ciphertext now contains **3,328 calendar events** reparsed in `America/Denver`, all 8 former 6–8 oz chicken ingredients normalized to 8 oz, and ingredient-based nutrition for the 4 formerly incomplete recipes. A second verification fetched the remote file, confirmed that personal collections were not present in plaintext, decrypted it in Chromium, and recovered the expected state.

The web release passed **100 unit tests** in 20 files and **126 Playwright tests** across desktop, tablet, and mobile Chromium. A separate exploratory walkthrough recorded **42 hands-on interactions** across every primary route, including creation, editing, planning, search, export, settings, navigation, persistence, and mobile layout checks. It reported no console errors, page exceptions, failed HTTP responses, or page-level horizontal overflow.

> **Meaning of complete:** A requirement is complete when the static web application can provide it safely and it has direct automated or hands-on evidence. Platform capabilities that require EventKit, native cameras, Photos, or Share Extensions remain intentionally assigned to the documented iPhone/iPad phase. Third-party browser requests remain subject to provider CORS and availability; MyHub provides a reviewed local or encrypted-repository path instead of claiming that a static page can bypass those restrictions.

## Remaining Boundaries

No unmet browser deliverable remains. The remaining items are product boundaries rather than defects: native Apple integrations belong to the iPhone/iPad implementation, public web APIs can be unavailable or blocked by CORS, and deleting the current GitHub file cannot erase Git history or provider retention.

The private link is a bearer capability and must remain private. Supabase stores only ciphertext, but anyone holding the link can resolve and decrypt that record in MyHub until a replacement link revokes the old broker row. The unlocked browser runtime necessarily holds decrypted AppData and backup credentials in memory. Users should retain the recovery passphrase, keep the data repository private, and periodically export a backup.
