# MyHub Requirements Audit

**Audit date:** 22 September 2026

**Code baseline:** `0e094f3` plus this cross-cutting hardening branch

**Companion work not yet credited here:** the next food-hardening and calendar-hardening branches
**Scope:** current web implementation, verification status, deliberate native-only boundaries, and static-browser integration limits

## Current Assessment

MyHub is a functional local-first web application, not a mockup. The combined baseline includes persisted school, food, pantry, grocery, settings, backup, encrypted GitHub Sync, and private-calendar snapshot workflows. This audit does **not** treat the companion food-hardening or calendar-hardening branches as merged. Rows that depend on those branches remain **implemented, hardening pending** until the parent integration verifies their final commits.

Cross-cutting evidence on this branch covers populated dashboard ordering, universal search across all indexed collections, plaintext backup export and validated import, and provider-level mocked GitHub Sync behavior. Playwright defines desktop, tablet, and mobile Chromium projects. The Pages workflow invokes the full `npm run test:e2e` command, so all 3 projects are part of CI rather than a desktop-only claim.

> **Status vocabulary:** **Complete web** means the capability is implemented and has direct automated evidence on the current combined tree. **Implemented, hardening pending** means the user-facing implementation exists at `0e094f3`, but final branch-specific evidence must be updated after the named hardening branch merges. **Browser-limited** means the static client provides an explicit fallback but cannot guarantee a third-party response or cross-origin request. **Native-only** means the requirement deliberately belongs to a future SwiftUI application and is not represented as web work.

## Data, Privacy, and Security Boundaries

| Control                              | Current status                                 | Verification and limit                                                                                                                                                                                                                                |
| ------------------------------------ | ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Empty production data                | **Complete web**                               | Missing state creates empty personal collections; test samples remain under `src/test`.                                                                                                                                                               |
| Local-first persistence              | **Complete web**                               | IndexedDB is the immediate working store and continues operating when optional sync is paused or offline. Browser/profile/origin storage can still be cleared by the platform.                                                                        |
| Schema migration                     | **Complete web**                               | Version 1 state and backups migrate to schema version 2; unsupported future versions are rejected.                                                                                                                                                    |
| Historical integrity                 | **Complete web**                               | Meals, food logs, and grocery history retain source/nutrition/item snapshots so later source edits do not rewrite history.                                                                                                                            |
| Credential separation                | **Complete web**                               | Repository coordinates, sync metadata, and encrypted token are stored outside `AppData`; backups and remote AppData snapshots exclude that credential record.                                                                                         |
| Secret handling                      | **Complete web with documented runtime limit** | No token, passphrase, private feed URL, calendar export, or personal backup belongs in source or tests. While unlocked, browser JavaScript necessarily holds the token and passphrase in memory; this is not equivalent to server-side OAuth custody. |
| Remote deletion                      | **Complete web with provider-retention limit** | The latest Contents path can be deleted and sync is paused. Git history, forks, caches, and provider retention may preserve earlier encrypted objects.                                                                                                |
| Accounts, advertising, and analytics | **Out of scope and absent**                    | The client includes no account system, behavioral analytics, advertising, or marketing tracker.                                                                                                                                                       |

## Final Integration Checklist

Before changing any **implemented, hardening pending** row to **complete web**, the parent integration should merge the relevant hardening branch, run `npm run check`, run the full 3-project Playwright suite, and record the actual result. It should then update the food/calendar rows and release evidence without rewriting the deliberate native-only or public-API/CORS boundaries.
